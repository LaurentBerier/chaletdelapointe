The chalet uses Supabase Auth for identity and the Express API for website permissions. Email confirmation submits an application; only administrator approval opens the member area. The declared relationship never assigns a role or permissions. Only confirmed owners see reservation names. Booking can be granted independently of the role. Members can request permission to book from their profile or the calendar. An administrator or the super administrator can approve that request; it does not reveal others’ reservation names or grant approval powers. Individual stays still require a separate approval. Only the super administrator can assign roles, suspend accounts, change existing access outside a request, and manage chalet settings. Self-registration never creates an owner or administrator.

Anonymous readers can obtain a five-minute signed URL only for a media path referenced by a published, unremoved article; server-validated paths prevent attaching another user's private upload. Removing/unpublishing an article prevents new public signed URLs; already issued URLs expire within five minutes. External HTTPS images remain hosted by their source. Unattached uploads remain private. Storage RLS uses narrow security-definer functions to check account/publication access without exposing private account or draft rows.
